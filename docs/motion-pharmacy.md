# 交互拆解：Hera 药房 App 录屏

作者在小红书刷到的「这么舒服的交互居然是个药房 App」（@flutterjourney，约 30 秒），按 8 帧/秒拆帧逐张看过。
这份记的是**它为什么舒服**、每一段用了什么手法，以及小手机里哪些地方用上了、哪些地方不能用。
动效的通用规则还是看 `DESIGN.md` 第 6 节；这里是一个具体的参考案例。

## 一句话总结

**每一次状态变化都「在原地」发生，并且有前因后果**：按钮自己变成结果（不是弹个提示），新页面从触发它的地方长出来，数字滚到新值，步骤一格一格点亮。
用户的眼睛从头到尾不用找东西，所以舒服。

## 逐段拆解

| 时间 | 发生了什么 | 手法 | 为什么舒服 |
|---|---|---|---|
| 0–1s 首页出场 | 头像地址 → 标题 → 四个快捷按钮 → 商品卡 → 底栏，依次出现 | Stagger（每块错开约 120ms）+ 从模糊到清晰（blur → 0）+ 轻微上浮；商品卡从右边滑进，右侧露出下一张卡的边 | 先给结构再给内容；露出的半张卡暗示「能往右滑」，不用写说明 |
| 1.5–2s 加购小按钮 | 商品卡右下的圆钮：一圈描边画出来 → 填满青色 → 出现对勾 | Morph（按钮原地变成结果）+ 描边绘制（stroke-dashoffset） | 结果出现在手指按的地方，不用看别处的提示 |
| 2.5s 点底栏扫描键 | 从按钮的位置长出一个圆，圆变大铺满屏幕变成相机页 | Reveal（clip-path 圆形揭开）+ Origin-aware | 空间关系清楚：相机是从这个键「打开」的，返回时知道回哪 |
| 3–4.5s 对准处方 | 画面从糊到清楚；顶部提示胶囊依次换字：对准处方 → 拿稳 → 已识别；拍照瞬间白闪 | 对焦模糊过渡；同一个胶囊里换字（带一点模糊的交叉淡入）；快门白闪 | 提示永远在同一个位置，只换内容；白闪给「拍到了」的确认 |
| 5–8s 读处方 | 一道青色扫描线带拖尾从上往下扫；快门键变成进度圈，中间数字 0% → 98% → 对勾；读到的每一行依次框上彩色描边框并贴小标签（Diagnosis / Medicine / Dosage / Supplement） | 扫描线（渐变拖尾 + 亮边）；进度圈 + 数字滚动；识别结果逐条出现 | 「机器正在干活」看得见；结果是一条一条长出来的，而不是一下子全冒出来 |
| 8.5s 分析完成 | 背景压暗，底部抽屉升起：标题 → 标签一个个弹出 → 推荐商品卡（98% match） | 底部抽屉（`--ease-drawer`）+ 内容 stagger | 结论出现在拇指够得到的位置，原图还在背景里能对照 |
| 9.5s 进商品页 | 新页从右边推进来，旧页往左退一小截 | Direction-aware + 视差（旧页只退约 1/4） | 两页像叠在一起的纸，前进后退方向一致 |
| 10–12s 加入购物车 | 按下去变小 → 黑色按钮变青色「✓ Added to Cart」→ 商品缩略图飞向右上角购物车 → 购物车角标数字弹一下 → 约 1 秒后按钮变回黑色 | 按压缩放；Morph；飞入购物车（共享元素的简化版）；角标 Pop | 一次操作有三个确认（按钮、飞的图、角标），但都在一条视线上 |
| 12.5–15s 购物车 / 优惠码 | 输入 HERA10 → Apply 变成青色「✓ Applied」；Discount 一行从上面挤进来；Total 从 $88.98 滚到 $80.08，结账按钮上的金额跟着变 | Morph；列表插入补间（FLIP）；Number ticker | 「省了多少」用动的数字表达，眼睛自然落到新数字上 |
| 16–17s 结账选项 | 选 Express：粗描边框从 Standard 移到 Express；支付方式的圆点跟着换 | 选中框位移（不是闪一下换掉） | 看得到「从哪个换到哪个」 |
| 17.5–19s 下单 | 按钮按下 → 文字换成「⟳ Processing…」→ 整页淡出 → 中间只剩一个青色圆 | Morph（按钮 → 加载 → 页面）；页面淡出 + 模糊 | 等待时有东西在动，但画面在变简单，注意力集中到结果 |
| 19–20.5s 下单成功 | 青色圆弹一下 → 对勾画出来 → 一圈光往外散 → 彩纸炸开飘落 → 「Order Placed!」从下往上浮出 | Pop（轻微过冲）+ 描边绘制 + 光圈脉冲 + 彩纸（只这一次） | 一整段里唯一的「惊喜」，放在最少发生的地方 |
| 21–24s 订单追踪 | 地图上路线一段段画出来；时间线的勾一个个点亮，竖线跟着往下填；骑手图标沿路线移动，地图慢慢放大 | 路径绘制；时间线 stagger；镜头缓推 | 「进行到哪一步」用位置和顺序表达 |

## 抽出来的规则（下次直接照着用）

1. **结果出现在触发的地方**：按钮自己变成「已完成」状态，不要另外弹提示；真的要提示，也从按钮的位置出来。
2. **新东西从来源长出来**：从按钮揭开、从缩略图放大、从底部升起；只有居中的对话框才从中心出现。
3. **一组东西错开出现**：30～120ms 一个；越重要越先出来（结构 → 标题 → 内容 → 操作）。
4. **「正在处理」要看得见**：扫描线、进度圈加百分比、逐条出结果。比一个转圈的菊花更让人愿意等。
5. **数字变化用滚动**：金额、计数、百分比，眼睛会被动的数字吸过去。
6. **惊喜只给一次**：整段只有下单成功放了彩纸；高频操作（加购、选项切换）只有短短的形变。
7. **成对出现的状态要有回程**：「✓ Added」1 秒后变回原样，下一次还能再按。
8. **前进 / 后退方向一致**：前进时旧页往左退一点（视差），返回时它跟着手指回来。

## 小手机里用上的（2026-10-30）

| 地方 | 用了什么 | 代码 |
|---|---|---|
| 所有页面切换 | 新页推进来时，下面那页往左退 22%；右滑返回时它跟着手指回来（规则 8） | `core.js` 的 `page` / `back` / 右滑返回，`style.css` 的 `.pg.in.under` |
| 生成任务完成的提示条 | 转圈变绿圆：弹一下 → 光圈散开 → 对勾一笔画出来；文字带一点模糊换上；消失时往上淡出（规则 6 的「缩小版」：提示条经常出现，所以只做 0.4 秒的形变，不放彩纸） | `core.js` 的 `task`，`style.css` 的 `.tk.ok` |
| 导入表情时本地读图里的字 | 正在读的那张有一道扫描线带拖尾从上往下扫；读出名字的标签高亮弹一下（规则 4） | `apps/chat/sticker.js` 的 `reviewPage`，`style.css` 的 `.rv-sl` |
| 余额 | 滚动数字（规则 5，上一轮已经做了） | `core.js` 的 `roll` |

## 不能用的地方

- **微信样式的页面**（聊天、红包、转账、朋友圈……）一律照真微信录屏做，不往里加这些效果。上面的页面视差是所有样式共用的切页手感，iOS 系统和微信切页时旧页本来也会往左退一截；如果作者真机对比觉得安卓微信不是这样，就给微信样式关掉（`.st-wx` 下不加 `.under` 位移）。
- 彩纸、大光圈这种「惊喜」只能放在很少发生的地方（比如以后商业街的一番赏抽中、心屿解锁），不要放在每天点很多次的按钮上。
- 地图路线、骑手移动这类镜头动画，小手机目前没有对应的场景，先记着。

## 以后可以用上的（还没做）

- 商业街（`apps/street/`）接功能时：「加入 → ✓ 已加入」按钮形变、商品飞进购物袋、角标弹一下、优惠后金额滚动、下单成功的对勾 + 彩纸。
- 一番赏 / 娃娃机抽中：从按钮的位置揭开结果页（clip-path 圆形），结果卡错开出场。
- 生成多步内容（论坛、心屿风景）时，用时间线一格格点亮代替单个转圈。
