# 通话：怎么做到顺滑（参考 StarHub）

作者发来的小红书「StarHub｜顺滑的流式语音通话」（福圓童子，仓库 Starhub-Tutorials/StarhubQiao，这边打不开，只看了笔记正文和视频）。
小手机的 `apps/chat/call.js` 照着这些思路做，界面照微信录屏。

## StarHub 的要点（笔记原话整理）

1. 通话要丝滑，就**通话只管说话**，不要一边通话一边让模型干复杂的事（会大大增加延迟）。
2. 通话里说的话单独做压缩记忆：普通聊天**知道电话里说了什么，但不逐字塞进上下文**，不占太多短期记忆。
3. 声音自然：发声、韵律、重音、语调、副语言（「嗯…」「哦…」「hey」这种垫音）。作者在评论区补充：**垫音可以提前准备好**，模型思考的时候先自然地垫一句，同时准备下一句。
4. 多语言：你说中文、他说英文都可以实时切换（视频里底部有 I SPEAK / HE SPEAKS 的 CN / EN 开关）。

## 小手机里怎么落地

| 环节 | 做法 | 为什么快 |
|---|---|---|
| 听我说话 | 浏览器自带的语音识别（Web Speech，免费，不走用户 API），一句话说完（停顿）就交给模型；不支持或没权限就打开「打字说」 | 不用先录音再上传识别 |
| 模型回话 | `llm(..., { stream: true, fast: 1, onText })` 流式拿字，**低思考** | 第一句字出来就能开始 |
| 切句 | 中文遇到 。！？… 或换行就切；一句超过 14 字遇到逗号也先切；外语一行一句（`原文 // 中文译文`） | 不等整段写完 |
| 合成 | 每句一切出来就立刻发去合成（用这个人的专属音色），**下一句在上一句播放时就在合成** | 句子之间几乎不停顿 |
| 播放 | 按顺序播；对方说话时不开麦（不然会把自己的声音录进去）；点屏幕可以打断，换我说 | 不会自己跟自己对话 |
| 记忆 | 挂断后存一条 `t:'call'` 消息：显示「通话时长 00:12」，`log` 里是通话内容；`say()` 给后面的聊天回复带最后十几句的摘录（≤400 字） | 普通聊天知道电话里聊了什么，但不占满上下文 |
| 提示词 | 「设置 → 应用配置 → 聊天 → 语音通话」可以改：完全口语、一次一两句、可以有语气词，不要动作描写和括号旁白 | 句子短，切得快 |

## 作者发来的 StarHub 教程 PDF（SPEC v1）对照

| 教程要求 | 小手机现在 |
|---|---|
| 只放出**已经稳定**的前缀：半句话、没闭合的括号 / 标签、没写完的双语行先留着，已放出的不再改 | `zhUnits` / `pairUnits`：括号、引号、`*动作*` 没闭合就不切；外语按整行处理；放出过的句子不撤回 |
| 中文按句末标点切，但要先处理括号和控制标签 | 。！？… / 换行切；14 字以上遇逗号先放；`clean()` 去掉括号旁白、星号动作，字幕和合成都不念 |
| 双语用明确行标记，释义只显示不合成 | 模型按 `SAY:` / `ZH:` 成对输出，只合成 SAY，ZH 显示在字幕下面 |
| 「我说的语言」和「TA 回答的语言」是两个独立选择；一轮开始时拍快照，中途切换只影响下一轮 | 通话页底部「我说 中文 ｜ TA 说 中文」两个开关；TA 的语言在每轮开始时读一次 |
| 背压：最多领先已播完位置两句，播完才往前 | `synth()` 只给「正在播的后面 2 句」发合成请求 |
| 浏览器按同一条音频时间轴排播，不要每块新建播放器、不要用 setTimeout 串 | 整通电话一个 `AudioContext`（在点击里建好），每句解码后排到 `max(上一句结束, 现在 + 0.05 秒)`；解不了码才退回 `<audio>` |
| 播完才算完成；取消时先停节点，迟到的回调不能推进新一轮 | 每轮一个 `AbortController`，挂断 / 打断时 abort；之后到的文字、音频、onended 都被丢掉 |
| 思考和播放期间关闭本轮输入，避免外放触发自答 | 对方说话时不开麦；对方思考时打字也不收（提示「等 TA 想好…」）；点屏幕是明确的打断 |
| 失败不能制造第二份回答 | 出错只结束这一轮（提示「对方没听清」），不偷偷重新生成 |
| 记录能解释体验的时间点，没实测就不声称零延迟 | 每轮第一句记下首声等了多久（通话记录里的 `ms`） |
| 不得自动调用付费合成或打开摄像头、麦克风 | 都只在你点了「通话」之后才开；视频通话才请求摄像头 |

教程第 10 节「自然人声合成规范」是给能调音色参数的合成引擎用的（声源、共鸣、停顿、重音、情绪……）。小手机用的 Fish / MiniMax 等服务大多只能选音色，所以只借用了两条：**台词里不放括号旁白和动作**（不然会被念出来），**一次只说一两句、短句**（停顿自然）。以后接上能控停顿 / 情绪的引擎，再按那一节逐项映射。

## 作者找到的仓库 StarhubQiao/Starhub-Tutorials（2026-10-30 看过）

里面只有四份教程文档（通话 SPEC v1、记忆系统 SPEC、实时视频陪伴·专注模式、咖啡机），没有 StarHub 应用本身的源码。通话那份和作者之前发的 PDF 是同一份。视频陪伴教程里有两条通话也用得上，已经做了：

- **常驻前缀整场冻结**：系统提示、人设、最近聊天在接通时算一次就不再变，每轮只在后面追加「想起来的旧事」「这通电话里说过的」「刚刚说」。前缀一字不差，模型那边的提示缓存才能命中，每轮起手快；测试里核对了两轮的系统提示和前缀完全一样。
- **半双工 + 防回声自激**：对方说话、思考时不开麦（外放会被麦克风收回去，变成「自己打断自己」）；现在是点「点这里说」才听，点「说完了」才发。

它那套 180 毫秒抖动缓冲是给「音频按小块流过来」用的；小手机的合成服务一句话回一个完整文件，句内不会抖，所以没抄。

## 为什么「对方正在想」会等很久（作者真机 2026-10-30：等了近一分钟）

- 走的是酒馆「当前连接」：酒馆的 `generateRaw` 不给流式，整段想完才回来；开着深度思考的模型（Gemini 等）想得更久。**解决**：设置 → 应用配置 → 聊天 → 语音通话 → 模型 选一个酒馆「连接配置」或自己的 API（这两条走流式），再把「低思考」打开。
- 界面现在会把等了几秒一直显示出来；超过 2.5 秒先放一句提前合成好的「嗯……我想想」；20 秒给出上面这条提示和「不等了」；2 分钟一个字没来算这轮失败，可以「重发刚才那句」。

## 还没做的（以后可以加）

- 垫音：每个音色提前合成几句「嗯…」「我想想」，模型思考超过 1 秒就先播一句。
- 我说话也能选语言（现在语音识别固定中文，`S.callLang` 可以改）。
- 对方主动打电话来（来电界面）。

## StarHub 记忆系统教程（第二份 PDF）里用上的

那份是给独立小手机写的（Python + SQLite 后端），小手机是酒馆插件，没有后端，所以只借思路：

- **磁铁召回**（`apps/chat/recall.js`）：回复只带最近 30 条聊天；更早的聊天里，和现在说到的词有关的几句被「吸」上来放进提示词。教程是用模型给每条记忆打标签；小手机为了**不多花 API**，改成直接用关键词（汉字两两一组、英文单词、假名），越少见的词越有分量，越久远的分越低。有字数上限（私聊 600 字、通话 400 字），什么都没想起来就整块不出现，不留「暂无」占位。
- **空块整块消失**：通话提示词里「最近的聊天」「这通电话里说过的」没内容就不写这一段。
- **测试先红后绿 + 变异对照**：写进了 AGENTS.md（这次修「微信列表看不见」就是先写检查、确认改前是红的再修）。

没用上的：SQLite 单库、每晚打标的水位线、动作标记的审计表、每日备份（这些都需要后端；小手机的数据跟着酒馆聊天走，「设置 → 数据」里已有导出 / 导入）。

## 2026-10-30：对照 StarHub 示例视频改的三件事

- 示例视频后半段（00:49 以后）是录屏时用小红书「长按 2.0x」快放的，通话计时走得比视频快一倍，不能当真实速度；前面 00:29–00:45 是原速，可以参考：对方说完、我一停，它马上接话。
- **酒馆当前连接也能流式**：以前走「酒馆当前连接」用的是 `generateRaw`，它不支持流式，必须整段想完才开口（这是「对方正在想」要等快一分钟的主要原因）。现在 `core.js` 的 `curReq` 在当前连接是聊天补全时，直接调酒馆自带的 `ChatCompletionService.processRequest`（`stream: true`），模型、密钥、代理都照「API 连接」页当前设置；低思考传 `reasoning_effort: 'min'`。文本补全或旧版酒馆没有这个服务时退回 `generateRaw`；流式失败且一个字都没出时也退回一次。只有传了 `stream` 的调用（目前只有通话）会走这条，正文回复不变。
- **自动接话（默认）**：TA 说完马上开麦，我停下 1.2 秒（识别结果不再变化）就自动轮到 TA；TA 想和说的时候麦是关着的（半双工，防外放自答）。底部「自动接话 / 点着说」可以切，设置存在 `S.callAuto`。
- **字幕逐字出**：每句按这句音频的时长匀速放字，外语下面的中文释义按比例同步出；打断或播完就整句显示。
- 还没做：语音合成按小块流式（教程里的 PCM 分块 + 0.5 秒起播缓冲）。现在是一句合成完再播，第一句短的话差别不大；要做得看各家语音接口支不支持分块返回。

## 2026-10-30：TauriTavern 里为什么录不进声音

- 查了 TauriTavern 的安卓源码（Darkatse/TauriTavern，2.4.0）：`AndroidManifest.xml` 没有声明 `RECORD_AUDIO`，网页要麦克风时它会去申请这个权限，但没声明的权限系统直接拒绝 → 网页里 getUserMedia、浏览器语音识别都拿不到声音。安卓内置网页本身也不提供浏览器语音识别。这不是插件能绕过去的。
- TauriTavern 的 `/api/backends/chat-completions/generate` 支持流式（ai-routes.js 里的 createChatCompletionStreamResponse），所以 curReq 在 Tauri 里也能一句一句出；请求带 `type: 'quiet'`，不当成正文生成。
- 做法：在 Tauri 里（有 `__TAURI_INTERNALS__` / `__TAURI__`）不开浏览器识别，轮到我就弹出输入框，用手机输入法自带的语音输入（键盘上的话筒；输入法有自己的麦克风权限）。自动接话开着时，框里的字 1.8 秒不再变就自动发出去。
- 以后如果 TauriTavern 加上了 RECORD_AUDIO：可以用 getUserMedia 录音，把音频跟本轮请求一起发给 Gemini（它能听音频），让模型先写出听到的话再回答，不多调一次模型。

## 2026-10-30：「模型听」——不再靠浏览器自带识别

- 用户在原生酒馆（浏览器）里也录不进：报 `network`（浏览器自带识别要把声音传到谷歌服务器，国内不开梯子连不上；很多国产手机没有谷歌服务，开了也不行）和 `audio-capture`（麦克风被录屏占着）。结论：浏览器自带识别在国内靠不住。
- 新做法（默认）：`getUserMedia` 自己开麦克风（回声消除、降噪、自动增益）→ ScriptProcessor 每帧算音量，噪声底自适应，连着约 0.13 秒够响就算开口（字幕位置出现跟音量跳的竖条），安静 1 秒算说完，不到 0.35 秒的不算 → 录音降到 16kHz 单声道 wav → 跟本轮请求一起发给模型（`llm(..., { audio })`）。走酒馆时是 `audio_url` 内容块，酒馆会转成 Gemini 的 inlineData（prompt-converters.js 里 convertGooglePrompt 支持）；走自己的 API 是 `input_audio`。
- 模型回复第一行是 `HEARD: 我说的原话`，填进字幕里我那一行、记进通话内容；后面照常切句、合成、逐字字幕。只调用一次模型，不用谷歌、不要额外的密钥。要 Gemini 这类能听音频的模型；听不了时提示把底部切成「浏览器识别」。
- 半双工：TA 想和说的时候不听，TA 说完再等 0.45 秒（回声尾巴）才开始听。麦克风一点声音都没有时提示可能被录屏占着。
- TauriTavern 里没有麦克风权限，还是输入法说；以后 TauriTavern 加上 RECORD_AUDIO，模型听可以直接用。
- 测试：`callear`（8824），假麦克风 + 音量控制。

## 2026-10-30：参考的 5 个开源项目，以及学过来的东西

| 项目 | 做法 | 能不能直接用 | 学到的 |
| --- | --- | --- | --- |
| mubai-ears（耳蜗 + 速记） | 电脑上本地 Whisper 转写 + 频谱图和音高 / 能量 / 停顿 / 语速数字给 AI 读 | 要电脑跑 Python，手机浏览器不行 | 让 AI「听语气」 |
| Ocean Listen（听海） | CLI，Parselmouth 声音分析、扒谱 | 运行内存 3–4G，手机不行 | 同上 |
| Companion Voice Runtime | VPS + AssemblyAI（收费）+ 腾讯，多识别仲裁，YAMNet 听非语言声音，安静 30 秒休眠 | 要服务器和收费识别 | 附和不打断、真想说才打断、转写错了能改、安静时不花钱 |
| PaiVoice（AGPL） | 实时语音层，温和打断 | 仓库评论说代码还没传全 | 附和不打断 |
| Audio8 TTS 0.1B | 端侧语音合成（说话，不是听） | 不相关 | — |

我们的「模型听」本来就不调用额外的收费服务：录音跟本轮请求一起交给正在用的 Gemini，它直接听原声，语气本来就听得出来。这次加了：

- **听语气**：提示词让模型认真听（笑 / 困 / 犹豫 / 撒娇 / 不高兴），HEARD 里把（笑）（叹气）写出来，回答自然接住语气。HEARD 的清理不去掉括号。
- **温和打断**：TA 想 / 说的时候也在听，门槛比平时高 2.5 倍（喇叭会漏进来一点 TA 的声音），连着说够 0.7 秒（TA 没出声在想时 0.45 秒）才打断；「嗯」一声不算。被打断的 TA 那句字幕后面加「—」。`S.callBarge` 为 false 可以关掉。
- **我还没说完**：TA 还在想的时候我又开口，当成上一句没说完：取消这一轮，把上一段录音 + 0.3 秒空白 + 新的一段合成一段重新发。
- **听错了能改**：点字幕里我说的那句，就地改字，通话内容跟着改。
- 安静时什么都不发，不花钱（只在听到说话时才发请求）。

## 2026-10-30：Tauri 里不能写「在听…」骗人

- 用户在 Tauri 里直接对着手机说话，界面写着「在听…」，其实没有任何东西在听（TauriTavern 2.4.0 最新代码仍没有 RECORD_AUDIO）。改成：拿不到麦克风时写「点下面的框，按键盘上的🎤说话」，并在下面说明原因；只有框里有焦点（键盘开着）才写「在听…」；用过一次之后写「点下面的框，接着说」。
- Tauri 里也先 `getUserMedia` 试一下：以后 TauriTavern 加了录音权限，就直接走模型听，不用再改代码。
- TA 想的时候显示「N 秒 · 模型思考了 M 字」（onThink）；这一轮没接上（报错 / 空回复 / 2 分钟没动静 / 我点了「不等了」）时，原因留在屏幕上（`A.why`），不只是一闪而过的提示。

## 2026-10-30：参考 evolia（开源安卓 App，dragonstaryuri-sys/evolia）重构「耳朵」

evolia 是原生安卓，自己有录音权限，链路是 录音（AEC3 + 降噪）→ Silero VAD → 识别（系统识别 / 本地 SenseVoice / 在线识别）→ 模型 → TTS。网页里做不了原生的，但同样的思路能搬：

- 拆出 `apps/chat/ear.js`：麦克风 → VAD → 识别，通过事件（start / level / partial / end / final / short / duck / unduck / barge / asrerr）告诉通话界面。`call.js` 只管状态和界面。
- **识别来源**：`model`（录音交给聊天模型听）/ `sf`（硅基流动免费识别模型，默认 FunAudioLLM/SenseVoiceSmall；evolia 默认 TeleAI/TeleSpeechASR）/ `web`（浏览器识别）/ Tauri 里输入法说。底部开关轮着切。硅基识别的密钥：`S.callAsr.key`，没填就用画图那里的硅基流动密钥，都没有就在通话界面里就地填。
- **伪流式**（照 evolia OnlineASRProvider）：切片 ≥1 秒且遇到 0.2 秒小停顿就切一段送去认；连着说超过 3 秒、当前这帧不响时强制切；前面认出来的字当 prompt 带上；按顺序排队，说完把最后一段认完再交出整句。说话时字幕边说边出字。
- **两段式打断**（照 evolia：240ms duck → 520ms interrupt）：TA 说话时连着响 6 帧（约 0.26 秒）先把 TA 音量压到 20%，连着响 14 帧（约 0.6 秒）才打断；中途不响就恢复。TA 在想（没出声）时 11 帧。
- 预卷 0.5 秒（插话时 1.2 秒），开口前几个字不被吞；回声尾窗从 0.45 秒改成 0.25 秒；垫音「嗯…」从 2.5 秒提前到 2 秒（evolia 的 LISTENER_CUE_DELAY_MS）。
- **TA 主动挂电话**（照 evolia 的 call_control 工具）：聊完了模型在最后单独写一行 `[挂断]`，放完这句就挂，字幕和记录里不露标记。
- 在认最后一段的时候（`A.recog`）不听新的，避免把同一句拆成两轮。

## 2026-10-30（voice-v2）：省请求次数 + 识别认错字按上下文改

- 用户的中转站限流：HTTP 429「1 分钟内最多请求 3 次」。原来说一段话中间停几下，本地识别就拆成好几句、每句一次请求，一下就超了，后面全失败。
- **先别急着发**：认出一句后等一小会儿（中转站有限额时 1.5 秒，没有 0.7 秒），期间我又开口就并成一句；我还在说就一直等。
- **限流排队**：碰到 429 从报错里读出「每分钟最多几次」记到 `S.callRpm`，这一分钟用满了就排队（状态行显示还要等几秒），时间到自动重发，不算失败（最多两次）。报错只留一句人话，不把 JSON 甩到屏幕上。
- **少花不必要的请求**：追问「还在吗」默认关（`S.callNudge` 要设成 true 才开）；有限额时接通那句「喂？」不调用模型。
- **认错字**：告诉模型「这是语音识别出来的字，可能有同音字认错」，明显认错时第一行写 `FIX: 改正后的原话`，字幕和通话内容跟着改；和回复是同一次请求。
- 「整通电话只调一次」做不到：每句回答都要模型现写，跟发消息一样，一句回复就是一次请求；OpenAI Realtime / Gemini Live 那种「一个会话」也是按用量计费，而且 DeepSeek / 普通中转都不支持。能做的是少发（合并）、每次轻一点（通话用的上下文本来就比正文短，前缀固定方便中转 / DeepSeek 的缓存命中）。

## 每轮开头都先来一句「おはよう。何かあったの？」（10-31 · 17）
模型的毛病，提示词压不住。改成代码兜底：TA 开过口以后，每句里的开场白小句（おはよう / もしもし / 喂 / 早上好…）和这通电话里说过的原句一字不差的，直接去掉，不念也不显示；中文释义按同样位置删（句数对不上就按释义内容删）。见 `dropSaid`。

## 每次打电话都「正在准备本地识别」
模型其实一个网页里只读一次，但读要几秒（39MB），以前是拨号时才开始读。现在进私聊 1.5 秒后就在后台先读（`warmEar`，只在用本地识别时），打过去基本就是现成的。网页被手机杀掉 / 刷新过，还是要重读一次。

## 重写通话提示词：真正的多轮对话（10-31 · 19）
以前把所有东西塞进一大段 user 文字（30 行规矩、我的话出现三遍、之前坏掉的通话记录也塞进「最近的聊天」），模型像在答题，还会被旧的乱话带偏（「选科」）。现在：
- **system** = 原来的剧情上下文（sysCtx）+ 一段很短的通话说明：你是谁、【此刻】（现在几点、照最新剧情先定好在哪在干嘛，整通电话保持一致）、最近的私聊（不含通话记录）、【之前的电话】（只有记住的，最多 2 通，带「多久前」）、【怎么说话】6 条。整通电话不变，缓存能命中。
- **messages** = 这通电话：我一句 user、TA 一句 assistant（外语按 SAY/ZH 写回去，模型照格式接着写）；最后一条就是我刚说的。`llm(..., { msgs })`：curReq / stReq / 自己的 API 都支持；酒馆文本补全（generateRaw）退回成一段文字。讲故事、「模型听」录音还走旧的一大段。
- 默认的通话模块提示词去掉「可以有嗯啊欸」（小模型理解成每句都要先来一下）。

## 快一点
- 日语：SAY 行一写完就开始合成，不等 ZH 那行（`pairUnits(pub, onZh)`），中文释义晚到再补进字幕和记录。
- 认完一句后等 0.3 秒（有每分钟限额的线路 1.2 秒）就发；云端校对最多等 0.9 秒。
- 提示词要求第一句尽量短（两三个字到半句），短句合成快，先出声。

## 通话记不记进记忆
- 通话底部「记住这通 / 不记这通」（记住 `S.callMem`，默认记）；聊天里长按通话记录也能改（`m.mem`）。
- 不记 = `forgot(m)`：私聊回复的上下文、回忆（recall）、正文注入、下次打电话都不带这通。旧的通话记录没有 `mem`，一律当不记（之前坏掉的通话不再喂回去）。
- 记住的：私聊上下文照旧带摘录；下次打电话放在【之前的电话】，写明「只当背景，以最新剧情为准，可以顺嘴提一句」。

## 不限制长短（10-31 · 21）
用户对比别的小手机：TA 一次能说长句、好几句，有性格。我们这边「一次 1～3 句」「第一句尽量短」把 TA 压成了「うん？」。现在：
- 【怎么说话】改成「照人设的性格和说话习惯，想说多少就说多少」，删掉句数和「第一句要短」。
- 一轮上限 4 句 → 12 句（只防失控）；模型写出「我的名字：」就是在替我说话，从那里掐掉。
- 上下文改回跟私聊回复一样的完整 `sysCtx()`（以前为了快截成正文 6 条、世界书 2500 字，TA 的人设被截掉了就只剩套话）。
- 【此刻】带上 TA 24 小时内的微信状态（如果有）。

## 推翻重写（10-31 · 22）：模型只写话，其余代码保证
前几版的毛病：发现一个问题就加一条规矩、一道过滤，免费小模型顾不过来，越改越乱（最后一次：日语那行写成中文、中文那行变成替我说话、日语音色硬念汉字成乱码）。重写后分成两个文件：
- `call-brain.js`（脑子）：
  - 背景 `base()`（人设、世界书、正文最近 10 条，拨号时算一次）+ `tail()`（此刻几点、最近私聊、记住的旧电话、6 行说话规矩、语言）。整通电话不变。
  - `messages()`：这通电话按真正的多轮对话发（我 user / TA assistant，最后一条就是我刚说的）。接通第一句也是模型写的：「电话接通了，你先开口，照剧情里刚发生的事说，不要只说一句喂」。
  - 语言写成跟正文一样的格式：`「日语原话」（中文意思）`——模型最熟；不再有 SAY / ZH 两行（小模型把两行当成两个人对话）。
  - `parser()`：流式切句。「」里按句末标点切小句，一句写完就念（不等后面的（中文意思））；（中文意思）到了补进字幕；中文模式一行一段。写出「我的名字：」就停。
  - `langOk / fixLang`：念之前检查语言。设成日语就必须是日语（纯汉字短句如「本当？」放行）；混进中文的句子先用酒馆自带翻译翻成日语再念，原来的中文当字幕；翻不了就不指定语言让语音服务自己认。绝不让日语音色硬念汉字。
  - `cues()`：（笑）（叹气）（小声）… → Fish Audio S2 的 `[laughing]` `[sighing]` `[whispering]`（S1 用圆括号；别的服务商去掉）。字幕里不显示。
- `call.js`：响铃时就开始生成第一句、合成好才接起来（最少响 1.5 秒，最多 15 秒）；一段话里的小句一句句念、字幕接着长；省略号后停 0.45 秒、换一段停 0.22 秒；不限制句数长短（只防失控 40 小句）。
- 去掉：固定的「喂？」、FIX 纠错、开场白过滤 dropSaid、pureSay、垫音「嗯」。

## 轮流说、不排队、第一句不提「喂」（10-31 · 23）
- 轮流说（照 StarHub 教程「本文以轮流说话为范围，不实现插话打断」）：TA 想和说的时候麦克风关着（ear 的 mode 只有 listen / off，去掉 busy、duck、barge、两段录音合并）。外放录不进去、杂音不打断、不会因为打断让智谱那边两个请求撞车。想让 TA 停：点一下屏幕。
- 去掉「每分钟几次」的排队（RPM / slot / gofree）。429、请求太多、并发、繁忙：悄悄等 2 秒重发一次，还不行提示「模型那边这会儿忙」。接通时把旧版存的 S.callRpmBy 清掉。
- 接通：给模型的只有「（X打来的电话，你刚接起来。）」，一个「喂」字都不提（提了小模型反而照说）；tail 里加【刚刚发生的】：正文最后两段，放在离对话最近的地方。
- 响铃 8 秒第一句还没好：取消这次生成，先接起来、把麦克风交给我。
- 电话专属的那段（tail）也整通冻住（只有中途换语言才重算），系统提示每轮一字不差，缓存能命中。

## 发给 TA 的内容（10-31 · 24）
正文里的标签由用户自己定：设置 → 上下文与世界书（全局）和聊天设置（这个聊天）里同一块区域（apps/settings/ctx-rules.js）。
- 规则在 core：`ctxRules(ch)`、`body(mes, R)`、`tagsIn()`。默认只有 content 要、thinking 不要；没分配过的标签不发。有「要」的标签就只取它们（几段 content 按顺序拼起来）；一个都没有就用整条。注释 `<!-- -->` 当成一个标签；「要」的标签里整个包着注释的（`<wechat><!-- 群聊 --></wechat>`）留里面的字；排版用的 HTML 标签只去尖括号。全在本地，不调模型。
- 世界书：整本 / 每条一个勾，勾掉的不发（全局 `S.ctxR.wiOff`，聊天 `ch.cfg.ctx.wi`）。旧版设成「关」的条目（`S.wi.ov = 0`）搬成不勾。
- 聊天设置里不再有「跟全局 / 单独设置」开关：直接显示现在会发什么，点了就只改这个聊天，旁边一个小点，点它恢复成全局。
- `sysCtx({ ch })`：私聊回复、打电话都按这个聊天的规则取正文和世界书。打电话：正文最新两条放【刚刚发生的】，背景里只放再往前两条（不重复）。
