# 通话：怎么做到顺滑（参考 StarHub）

作者发来的小红书「StarHub｜顺滑的流式语音通话」（福圓童子，仓库 Starhub-Tutorials/StarhubQiao，这边打不开，只看了笔记正文和视频）。
小手机的 `apps/chat/call.js` 照着这些思路做，界面照微信录屏。

## StarHub 的要点（笔记原话整理）

1. 通话要丝滑，就**通话只管说话**，不要一边通话一边让模型干复杂的事（会大大增加延迟）。
2. 通话里说的话单独做压缩记忆：普通聊天**知道电话里说了什么，但不逐字塞进上下文**，不占太多短期记忆。
3. 声音自然：发声、韵律、重音、语调、副语言（「嗯…」「哦…」「hey」这种垫音）。作者在评论区补充：**垫音可以提前准备好**，模型思考的时候先自然地垫一句，同时准备下一句。
4. 多语言：你说中文、他说英文都可以实时切换（视频里底部有 I SPEAK / HE SPEAKS 的 CN / EN 开关）。

## 小手机里怎么落地

| 环节 | 做法 | 为什么快 |
|---|---|---|
| 听我说话 | 浏览器自带的语音识别（Web Speech，免费，不走用户 API），一句话说完（停顿）就交给模型；不支持或没权限就打开「打字说」 | 不用先录音再上传识别 |
| 模型回话 | `llm(..., { stream: true, fast: 1, onText })` 流式拿字，**低思考** | 第一句字出来就能开始 |
| 切句 | 中文遇到 。！？… 或换行就切；一句超过 14 字遇到逗号也先切；外语一行一句（`原文 // 中文译文`） | 不等整段写完 |
| 合成 | 每句一切出来就立刻发去合成（用这个人的专属音色），**下一句在上一句播放时就在合成** | 句子之间几乎不停顿 |
| 播放 | 按顺序播；对方说话时不开麦（不然会把自己的声音录进去）；点屏幕可以打断，换我说 | 不会自己跟自己对话 |
| 记忆 | 挂断后存一条 `t:'call'` 消息：显示「通话时长 00:12」，`log` 里是通话内容；`say()` 给后面的聊天回复带最后十几句的摘录（≤400 字） | 普通聊天知道电话里聊了什么，但不占满上下文 |
| 提示词 | 「设置 → 应用配置 → 聊天 → 语音通话」可以改：完全口语、一次一两句、可以有语气词，不要动作描写和括号旁白 | 句子短，切得快 |

## 作者发来的 StarHub 教程 PDF（SPEC v1）对照

| 教程要求 | 小手机现在 |
|---|---|
| 只放出**已经稳定**的前缀：半句话、没闭合的括号 / 标签、没写完的双语行先留着，已放出的不再改 | `zhUnits` / `pairUnits`：括号、引号、`*动作*` 没闭合就不切；外语按整行处理；放出过的句子不撤回 |
| 中文按句末标点切，但要先处理括号和控制标签 | 。！？… / 换行切；14 字以上遇逗号先放；`clean()` 去掉括号旁白、星号动作，字幕和合成都不念 |
| 双语用明确行标记，释义只显示不合成 | 模型按 `SAY:` / `ZH:` 成对输出，只合成 SAY，ZH 显示在字幕下面 |
| 「我说的语言」和「TA 回答的语言」是两个独立选择；一轮开始时拍快照，中途切换只影响下一轮 | 通话页底部「我说 中文 ｜ TA 说 中文」两个开关；TA 的语言在每轮开始时读一次 |
| 背压：最多领先已播完位置两句，播完才往前 | `synth()` 只给「正在播的后面 2 句」发合成请求 |
| 浏览器按同一条音频时间轴排播，不要每块新建播放器、不要用 setTimeout 串 | 整通电话一个 `AudioContext`（在点击里建好），每句解码后排到 `max(上一句结束, 现在 + 0.05 秒)`；解不了码才退回 `<audio>` |
| 播完才算完成；取消时先停节点，迟到的回调不能推进新一轮 | 每轮一个 `AbortController`，挂断 / 打断时 abort；之后到的文字、音频、onended 都被丢掉 |
| 思考和播放期间关闭本轮输入，避免外放触发自答 | 对方说话时不开麦；对方思考时打字也不收（提示「等 TA 想好…」）；点屏幕是明确的打断 |
| 失败不能制造第二份回答 | 出错只结束这一轮（提示「对方没听清」），不偷偷重新生成 |
| 记录能解释体验的时间点，没实测就不声称零延迟 | 每轮第一句记下首声等了多久（通话记录里的 `ms`） |
| 不得自动调用付费合成或打开摄像头、麦克风 | 都只在你点了「通话」之后才开；视频通话才请求摄像头 |

教程第 10 节「自然人声合成规范」是给能调音色参数的合成引擎用的（声源、共鸣、停顿、重音、情绪……）。小手机用的 Fish / MiniMax 等服务大多只能选音色，所以只借用了两条：**台词里不放括号旁白和动作**（不然会被念出来），**一次只说一两句、短句**（停顿自然）。以后接上能控停顿 / 情绪的引擎，再按那一节逐项映射。

## 作者找到的仓库 StarhubQiao/Starhub-Tutorials（2026-10-30 看过）

里面只有四份教程文档（通话 SPEC v1、记忆系统 SPEC、实时视频陪伴·专注模式、咖啡机），没有 StarHub 应用本身的源码。通话那份和作者之前发的 PDF 是同一份。视频陪伴教程里有两条通话也用得上，已经做了：

- **常驻前缀整场冻结**：系统提示、人设、最近聊天在接通时算一次就不再变，每轮只在后面追加「想起来的旧事」「这通电话里说过的」「刚刚说」。前缀一字不差，模型那边的提示缓存才能命中，每轮起手快；测试里核对了两轮的系统提示和前缀完全一样。
- **半双工 + 防回声自激**：对方说话、思考时不开麦（外放会被麦克风收回去，变成「自己打断自己」）；现在是点「点这里说」才听，点「说完了」才发。

它那套 180 毫秒抖动缓冲是给「音频按小块流过来」用的；小手机的合成服务一句话回一个完整文件，句内不会抖，所以没抄。

## 为什么「对方正在想」会等很久（作者真机 2026-10-30：等了近一分钟）

- 走的是酒馆「当前连接」：酒馆的 `generateRaw` 不给流式，整段想完才回来；开着深度思考的模型（Gemini 等）想得更久。**解决**：设置 → 应用配置 → 聊天 → 语音通话 → 模型 选一个酒馆「连接配置」或自己的 API（这两条走流式），再把「低思考」打开。
- 界面现在会把等了几秒一直显示出来；超过 2.5 秒先放一句提前合成好的「嗯……我想想」；20 秒给出上面这条提示和「不等了」；2 分钟一个字没来算这轮失败，可以「重发刚才那句」。

## 还没做的（以后可以加）

- 垫音：每个音色提前合成几句「嗯…」「我想想」，模型思考超过 1 秒就先播一句。
- 我说话也能选语言（现在语音识别固定中文，`S.callLang` 可以改）。
- 对方主动打电话来（来电界面）。

## StarHub 记忆系统教程（第二份 PDF）里用上的

那份是给独立小手机写的（Python + SQLite 后端），小手机是酒馆插件，没有后端，所以只借思路：

- **磁铁召回**（`apps/chat/recall.js`）：回复只带最近 30 条聊天；更早的聊天里，和现在说到的词有关的几句被「吸」上来放进提示词。教程是用模型给每条记忆打标签；小手机为了**不多花 API**，改成直接用关键词（汉字两两一组、英文单词、假名），越少见的词越有分量，越久远的分越低。有字数上限（私聊 600 字、通话 400 字），什么都没想起来就整块不出现，不留「暂无」占位。
- **空块整块消失**：通话提示词里「最近的聊天」「这通电话里说过的」没内容就不写这一段。
- **测试先红后绿 + 变异对照**：写进了 AGENTS.md（这次修「微信列表看不见」就是先写检查、确认改前是红的再修）。

没用上的：SQLite 单库、每晚打标的水位线、动作标记的审计表、每日备份（这些都需要后端；小手机的数据跟着酒馆聊天走，「设置 → 数据」里已有导出 / 导入）。

## 2026-10-30：对照 StarHub 示例视频改的三件事

- 示例视频后半段（00:49 以后）是录屏时用小红书「长按 2.0x」快放的，通话计时走得比视频快一倍，不能当真实速度；前面 00:29–00:45 是原速，可以参考：对方说完、我一停，它马上接话。
- **酒馆当前连接也能流式**：以前走「酒馆当前连接」用的是 `generateRaw`，它不支持流式，必须整段想完才开口（这是「对方正在想」要等快一分钟的主要原因）。现在 `core.js` 的 `curReq` 在当前连接是聊天补全时，直接调酒馆自带的 `ChatCompletionService.processRequest`（`stream: true`），模型、密钥、代理都照「API 连接」页当前设置；低思考传 `reasoning_effort: 'min'`。文本补全或旧版酒馆没有这个服务时退回 `generateRaw`；流式失败且一个字都没出时也退回一次。只有传了 `stream` 的调用（目前只有通话）会走这条，正文回复不变。
- **自动接话（默认）**：TA 说完马上开麦，我停下 1.2 秒（识别结果不再变化）就自动轮到 TA；TA 想和说的时候麦是关着的（半双工，防外放自答）。底部「自动接话 / 点着说」可以切，设置存在 `S.callAuto`。
- **字幕逐字出**：每句按这句音频的时长匀速放字，外语下面的中文释义按比例同步出；打断或播完就整句显示。
- 还没做：语音合成按小块流式（教程里的 PCM 分块 + 0.5 秒起播缓冲）。现在是一句合成完再播，第一句短的话差别不大；要做得看各家语音接口支不支持分块返回。
